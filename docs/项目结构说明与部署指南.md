# 知阶 Agent 项目结构说明与部署指南

> 本文依据当前仓库源码编写，适用于本地开发、结项展示和后续交接。当前版本已完成 Assistant Chat 的 FastAPI Proxy 与 API Key 后移；Materials、Quiz、Mastery、ReviewTask 等业务仍主要运行在浏览器中。

## 一、环境要求

| 项目 | 要求或建议 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10/11、macOS、Linux | 文档同时提供 PowerShell 和 Bash 命令 |
| Node.js | 建议 Node.js 20 LTS 或更高版本 | `package.json` 未声明 `engines`；前端使用 Vite 7、TypeScript 5.9 |
| 包管理器 | npm（仓库含 `package-lock.json`） | 建议使用 npm；无需同时使用 pnpm/yarn |
| Python | Python 3.10 或更高版本 | 后端使用 `str \| None`、`list[...]` 等类型语法 |
| FastAPI / Uvicorn | FastAPI `>=0.115,<1.0`；Uvicorn `>=0.30,<1.0` | 以 `backend/requirements.txt` 为准 |
| HTTP 客户端 | httpx `>=0.27,<1.0` | 后端请求 OpenAI-compatible API |
| 网络 | 本地前后端需互通；真实模型模式需访问模型供应商 | 仅使用 mock 时不要求访问外部 LLM |
| LLM API | OpenAI-compatible `/chat/completions` | 需要有效的 Base URL、Model 和 API Key |

安全约定：

- 前端不再要求或保存真实 LLM API Key。
- API Key、Base URL 和 Model 应配置在 `backend/.env`。
- 后端不会通过 `/health` 或 `/agent/chat` 返回 API Key。
- 未配置 API Key或模型调用失败时，`LLM_MOCK_FALLBACK=true` 会启用 mock fallback。
- 前端无法访问后端时，仍会落回现有前端 mock，保证演示页面可用。

## 三、当前系统架构

### 改动前

```text
Frontend Browser
  ↓ 携带浏览器中的 API Key
OpenAI-compatible API
```

主要问题：

- API Key 暴露在浏览器和网络请求中。
- Base URL、Model、API Key 曾保存在 `learning-agent-model-config` localStorage。
- 缺少统一的后端错误处理、模型配置管理和调用边界。
- 前端承担 prompt、模型请求、数据处理和页面状态等过多职责。

### 第一轮改动后

```text
React Frontend
  ↓
frontend/src/api/client.ts
  ↓ HTTP JSON
FastAPI Router: POST /agent/chat
  ↓
agent_chat_service.py
  ├─ 成功 → openai_compatible.py
  │          ↓ Bearer LLM_API_KEY
  │        OpenAI-compatible API
  └─ 失败且允许 fallback → mock.py
  ↓
AgentChatResponse
  ↓
llmClient.ts 结构化解析 / 现有前端 fallback
  ↓
React state 与 UI
```

各层职责：

- **React Frontend**：页面展示、用户输入、加载状态和临时 UI 状态。
- **Frontend API Client**：集中管理后端地址、JSON 请求、HTTP 错误和后端不可达的降级结果。
- **FastAPI Router**：声明 URL、HTTP 方法，校验 request body，返回 response model。
- **Service Layer**：编排真实 provider 和 mock fallback，并生成后端 trace step。
- **LLM Provider**：拼接 `/chat/completions` 地址，携带后端 Key，请求 OpenAI-compatible 服务并校验响应。
- **Environment Variables**：在后端保存 API Key、Base URL、Model 和 fallback 开关。
- **`llmClient.ts`**：目前仍保留 prompt 构建、JSON 修复、响应规范化和已有 mock；不再直接携带第三方 Key。

旧的 `learning-agent-model-config` 会在 App 启动时从 localStorage 删除。Settings 页面不再提供 API Key、Base URL、Model 输入框，其“测试连接”只请求后端 `/health`。

## 四、环境变量配置

后端会读取 `backend/.env`；如果同名系统环境变量已经存在，则系统环境变量优先。

### PowerShell

```powershell
cd zhijie-agent-demo\backend
Copy-Item .env.example .env
```

### macOS / Linux

```bash
cd zhijie-agent-demo/backend
cp .env.example .env
```

编辑 `.env`，不要填写到前端文件中：

```env
LLM_API_KEY=your_api_key_here
LLM_BASE_URL=https://api.example.com/v1
LLM_MODEL=your-model-name
LLM_MOCK_FALLBACK=true
```

| 变量 | 作用 |
| --- | --- |
| `LLM_API_KEY` | 后端请求模型服务时放入 `Authorization: Bearer ...` 的密钥 |
| `LLM_BASE_URL` | OpenAI-compatible API 基础地址；可填写 `/v1` 或完整 `/chat/completions` 地址 |
| `LLM_MODEL` | 发送给模型服务的 model 名称 |
| `LLM_MOCK_FALLBACK` | `true` 时，缺少配置、网络错误、HTTP 错误或响应异常会返回 mock |

注意：

- 不要提交真实 `backend/.env`；该文件已被 `backend/.gitignore` 忽略。
- `backend/.env.example` 可以提交，但只能包含占位符或公开默认值。
- `frontend/.env` 只能配置自己的后端地址，例如：

```env
VITE_API_BASE_URL=http://127.0.0.1:8000
```

- 任何以 `VITE_` 开头的变量都会进入浏览器构建产物，绝不能存放 LLM API Key。

## 七、访问与使用流程

1. 启动 FastAPI 后端和 Vite 前端。
2. 浏览器打开 `http://localhost:5173`。
3. 从工作台侧栏进入 **Assistant / 问 AI Agent**。
4. 输入学习问题，例如“为什么反向传播需要链式法则？”。
5. 前端先在浏览器中选择相关资料片段并构建 prompt。
6. `frontend/src/api/client.ts` 将 messages 发送到 `POST /agent/chat`。
7. 后端读取环境变量并调用 OpenAI-compatible API；失败时按配置返回 mock。
8. `llmClient.ts` 解析结构化回答，再由 React 更新消息、卡片候选和 Trace 等现有状态。
9. 未配置 Key、上游失败或 FastAPI 不可达时，系统应显示 fallback 内容，而不是导致整个页面崩溃。

这里的资料检索仍是前端关键词匹配与 prompt 注入，不是向量数据库或完整 RAG 服务。

## 八、API 接口说明

当前 FastAPI 只实现两个接口：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/health` | GET | 检查后端存活、模型配置是否完整、mock 是否启用 |
| `/agent/chat` | POST | 接收 messages，由后端代理调用 OpenAI-compatible LLM或返回 mock |

### `/health`

请求：

```text
GET /health
```

响应示例：

```json
{
  "status": "ok",
  "modelConfigured": true,
  "mockFallback": true
}
```

`modelConfigured: true` 只表示 Key、Base URL、Model 非空，不代表已经完成一次真实模型请求。

PowerShell 验证：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

### `/agent/chat`

Request Body：

```json
{
  "messages": [
    {
      "role": "user",
      "content": "帮我解释 cache 的局部性原理"
    }
  ],
  "metadata": {
    "sessionId": "demo-session",
    "source": "assistant",
    "maxTokens": 1800,
    "jsonMode": false,
    "temperature": 0.3
  }
}
```

字段约束：

- `messages` 至少一条；role 只能是 `system`、`user`、`assistant`。
- `metadata` 可省略。
- `maxTokens` 范围为 1～16000。
- `temperature` 范围为 0～2。
- `jsonMode=true` 时后端会优先请求 JSON response format；不兼容的供应商返回 400/404/422 时会去掉该参数重试一次。

真实模型响应示例：

```json
{
  "mode": "llm",
  "answer": "模型返回的文本内容",
  "raw": {
    "choices": []
  },
  "trace": [
    {
      "id": "llm_example",
      "title": "Backend LLM proxy",
      "type": "llm_call",
      "status": "success",
      "detail": "OpenAI-compatible request completed with model your-model-name."
    }
  ],
  "warning": null
}
```

Mock 响应仍具有相同字段，但 `mode` 为 `mock`，`answer` 是符合现有前端 Agent JSON 契约的字符串，`warning` 说明触发原因。

PowerShell 验证：

```powershell
$body = @{
  messages = @(
    @{ role = "user"; content = "帮我解释 cache 的局部性原理" }
  )
  metadata = @{
    sessionId = "demo-session"
    source = "assistant"
  }
} | ConvertTo-Json -Depth 5

Invoke-RestMethod `
  -Method Post `
  -Uri http://127.0.0.1:8000/agent/chat `
  -ContentType "application/json" `
  -Body $body
```

## 十、常见问题

### 1. 后端启动失败

依次检查：

- Python 是否为 3.10+：`python --version`。
- 是否在 `zhijie-agent-demo/backend` 目录运行。
- 虚拟环境是否创建并安装 `requirements.txt`。
- `uvicorn` 是否来自当前虚拟环境。
- 8000 端口是否被其他进程占用。

### 2. `/health` 无法访问

检查：

- Uvicorn 是否正在运行且没有启动异常。
- 地址是否为 `http://127.0.0.1:8000/health`。
- 是否修改过后端端口。
- 防火墙、系统代理或容器端口映射是否阻止访问。

### 3. Assistant 无法返回真实 LLM 回复

检查：

- `backend/.env` 是否存在，且位于 `backend` 根目录。
- `LLM_API_KEY` 是否有效。
- `LLM_BASE_URL` 是否为 OpenAI-compatible 地址。
- `LLM_MODEL` 是否是该供应商实际可用的模型名。
- 后端机器是否可以访问模型服务。
- 后端控制台是否出现 401、404、429、超时或响应格式错误。

### 4. 如何确认前端没有继续直连第三方 LLM

- 浏览器 Network 中 Chat 请求应指向 `http://127.0.0.1:8000/agent/chat` 或配置的 `VITE_API_BASE_URL`。
- `frontend/src/api/client.ts` 只请求 `/health` 和 `/agent/chat`。
- 浏览器请求中不应出现第三方 `Authorization: Bearer ...`。
- Settings 不再提供第三方 API Key 输入框。
- App 会删除旧的 `learning-agent-model-config` localStorage 项。

### 5. 为什么触发 mock fallback

可能原因：

- 后端未配置 Key/Base URL/Model。
- 模型供应商不可达或请求超时。
- API Key 无效、额度不足或被限流。
- 模型名或 Base URL 不正确。
- 上游返回非 JSON、空 content 或不符合 OpenAI-compatible 格式。
- FastAPI 后端未启动，前端自动使用现有 mock。

若 `LLM_MOCK_FALLBACK=false`，后端 provider 错误会以 HTTP 502 返回；前端当前仍会将该请求错误降级到自己的 mock，以保证 Demo 可用。

### 6. 端口冲突

修改后端端口：

```powershell
uvicorn app.main:app --reload --host 0.0.0.0 --port 8001
```

然后在 `frontend/.env` 中同步修改：

```env
VITE_API_BASE_URL=http://127.0.0.1:8001
```

修改 Vite 端口时，需要同时更新 `frontend/vite.config.ts`，并把新前端 Origin 加入 `backend/app/main.py` 的 CORS allow list。目前后端只允许 `localhost:5173` 和 `127.0.0.1:5173`。

### 7. 修改 `.env` 后为什么没有生效

`get_settings()` 使用进程内缓存。修改 `.env` 后应重启 Uvicorn；开发模式下文件变化不一定会因 `.env` 自动触发 reload。

## 十二、工程学习点

### API Proxy

浏览器只请求自己的 FastAPI，FastAPI 再携带密钥访问模型服务。这样 Key 不进入前端代码、localStorage 或浏览器第三方请求，也为后续限流、审计和 provider 切换提供统一入口。

### Endpoint

Endpoint 是 HTTP 方法与 URL 的组合。例如 `GET /health` 对应 health router 中的函数，`POST /agent/chat` 对应 agent chat router。Router 负责协议边界，而不是承担全部业务逻辑。

### Request Body

Request Body 是前端发给后端的 JSON。本项目用 Pydantic 校验 messages、metadata、role、maxTokens 和 temperature，使错误输入在进入 provider 前就被拒绝。

### Response

Response 是后端返回的稳定契约。当前 `AgentChatResponse` 包含 `mode`、`answer`、`raw`、`trace`、`warning`，前端据此区分真实模型和 fallback。

### Environment Variables

API Key 属于服务端秘密，不应进入 Git 或浏览器。`.env` 方便本地配置，生产环境可改用部署平台的 Secret/Environment 管理；`.env.example` 只描述变量名和占位值。

### Frontend API Client

统一 API client 可以集中处理后端地址、JSON 解析、HTTP 错误和 fallback。页面组件不需要到处写 fetch，也不会意外携带第三方 Key。

### Service Layer

Service Layer 承接“调用 provider、失败是否 fallback、怎样组织结果”等业务规则。后续 Quiz、Mastery、Review 也应逐步采用同一方式，从 `App.tsx` 中移出。

### localStorage vs Database

主题、折叠状态等单机 UI 偏好适合 localStorage。Mastery、复习任务、Quiz 结果、错题、会话和可信 Trace 属于业务事实，需要可靠查询、事务、用户隔离和跨设备同步，更适合后端数据库。

### Mock Fallback

结项 Demo 需要在无 Key、网络不稳定或模型服务失败时仍可展示主流程。Mock 是明确的降级路径，不应伪装成真实模型；因此 response 中保留 `mode` 和 `warning`，便于 UI 与 Trace 说明真实来源。
